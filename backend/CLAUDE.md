# Backend 규칙

## 명령어 (backend 폴더에서)
- 전체 테스트: `./gradlew test`
- 단일 테스트: `./gradlew test --tests "*CourseServiceTest"`
- 포맷: `./gradlew spotlessApply` (커밋 전), 검사는 `./gradlew build`에 포함
- 실행: `./gradlew bootRun` (기본 dev 프로필)
- Gradle은 JDK 21 이상으로 실행한다. 이 PC의 PATH 기본값은 JDK 8이라 `JAVA_HOME`을 `~/.jdks/openjdk-23`으로 지정해야 한다
- JDK 23에서 `Unable to establish loopback connection`이 나면 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=D:/tmp-jdk`

## DB
- dev·test 프로필 모두 H2 인메모리(PostgreSQL 호환 모드)다 (D-00). 운영 대상은 PostgreSQL
- 마이그레이션 SQL은 H2와 PostgreSQL에서 모두 동작하게 쓴다 (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, `TEXT`·`BIGSERIAL` 금지)
- 개발용 데이터는 `db/dev-data`에만 둔다 (dev 프로필에서만 실행)

## 패키지 구조
- 도메인별 패키지(`course`, `enrollment`) 안에 Entity, Repository, Service, Controller, `dto`를 둔다
- 공통 예외·에러 응답·설정은 `common` 패키지

## 계층과 JPA
- Controller → Service → Repository. Controller에서 Repository를 직접 부르지 않는다
- 업무 규칙(종료 과정 수정 금지, 정원 1 이상 등)은 엔티티 메서드에 둔다. 서비스는 조회하고 위임한다
- `@ManyToOne`은 항상 `fetch = FetchType.LAZY`. 엔티티에 `@Setter` 금지, 상태 변경은 `close()` 같은 메서드로
- 엔티티를 API 응답으로 반환하지 않는다. DTO는 `record`
- `open-in-view=false`, `ddl-auto=validate`. 스키마 변경은 Flyway(`V{번호}__{설명}.sql`)로만
- 목록 조회에서 연관 엔티티를 행마다 지연 로딩하지 않는다 (N+1). 집계는 쿼리 안에서

## API / OpenAPI
- URL은 `/api/v1/{복수형 리소스}`. 컨트롤러에 `@Tag`, 메서드에 `@Operation(summary)`, 실패 응답 `@ApiResponse`
- 페이지는 0부터 시작하고 응답은 `PageResponse<T>`(content, page, size, totalElements)
- 에러는 `common.error.ErrorResponse`(code, message), 예외는 `GlobalExceptionHandler`에서 변환

## 테스트
- 서비스: JUnit 5 + Mockito, 이름은 `메서드_조건_결과`, `@DisplayName`은 한국어
- 컨트롤러: `@WebMvcTest` + `@MockitoBean`
- 리포지토리: `@DataJpaTest` + `@ActiveProfiles("test")`, Flyway 스키마로 검증
